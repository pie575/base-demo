## 概述 {#overview}

[rollup 节点][g-rollup-node]是负责从 L1 区块 (及其关联的[收据][g-receipts]) 中[派生 L2 链][g-derivation]的组件。

rollup 节点中负责派生 L2 链的部分称为 [rollup 驱动程序][g-rollup-driver]。本文档目前仅涵盖 rollup 驱动程序的规范。

## 驱动程序 {#driver}

[rollup 节点][g-rollup-node]中[驱动程序][g-rollup-driver]的任务是管理[派生][g-derivation]过程：

* 跟踪 L1 头部区块
* 跟踪 L2 链的同步进度
* 每当有新的输入可用时，迭代执行各个派生步骤

### 派生 {#derivation}

该过程分为三个步骤：

1. 以最新的 L2 区块为基础，从 L1 链中选取输入：
   即一组区块，包含交易及其相关数据和收据。
2. 读取 L1 信息、存款和排序批次，以生成 [payload attributes][g-payload-attr]
   (本质上是[不含输出属性的区块][g-block]) 。
3. 将 payload attributes 传递给[执行引擎][g-exec-engine]，由其计算出 L2 区块 (包括[输出区块
   属性][g-block]) 。

虽然从概念上讲，该过程是一个从 L1 链映射到 L2 链的纯函数，但在实际中是增量执行的。每当有新的 L1 区块加入 L1 链时，
L2 链就会随之扩展。同理，每当
L1 链发生[重组][g-reorg]时，L2 链也会随之重组。

有关 L2 区块派生的完整规范，请参阅 [L2 区块派生文档](/zh/specifications/base-protocol/consensus/derivation)。

Rollup 节点的 RPC 接口规范详见 [RPC](/zh/specifications/base-protocol/consensus/rpc) 文档。

## 协议版本跟踪 {#protocol-version-tracking}

rollup 节点应通过监控 L1 上的 Protocol Versions 合约，
来跟踪推荐协议版本和必需协议版本。

这可以通过在 [Driver](#driver) 循环中轮询来实现。
轮询获取协议版本后，rollup 节点 SHOULD (应当) 通过
[`engine_signalSuperchainV1`](/zh/specifications/base-protocol/execution/l2-execution-engine) 调用将其告知执行引擎。

当推荐版本高于 rollup 节点当前支持的版本时，
rollup 节点 SHOULD (应当) 向用户发出警告。

如果 rollup 节点未达到必需的协议版本，则 SHOULD (应当) 采取安全防范措施，
例如在征得 rollup 节点运营者同意后停止引擎。
