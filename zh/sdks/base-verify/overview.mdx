借助 Base Verify，用户可以证明自己控制着已验证账户，而无需向你的应用暴露其凭据。你可以用它来抵御女巫攻击、防止同一用户通过多个钱包重复参与，并根据已验证的特征对操作进行准入控制。

## 两种集成方式的区别 {#how-the-integrations-differ}

|             | 验证社交账户                   | 在链上验证用户                     |
| ----------- | ------------------------ | --------------------------- |
| 校验执行方       | 你的应用后端                   | 你的智能合约                      |
| 使用的 Base 服务 | Base Verify REST API     | Base Verify REST API 和链上合约  |
| 返回结果        | 验证令牌和特征属性                | 已签名的 `identityHash`、过期时间和签名 |
| 适用场景        | 有访问门槛的应用体验、奖励，以及由后端控制的领取 | 合约层面的领取、存款、铸造、投票及其他链上操作     |
| 应用后端        | 必需                       | 领取时无需                       |

两种集成方式都以钱包签名的 SIWE 消息作为凭证，证明请求方控制该钱包。Base Verify 会评估所请求的提供方或策略，并且只返回所选流程需要的验证数据。
