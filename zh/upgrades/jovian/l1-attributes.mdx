## 概述 {#overview}

L1 区块属性交易已更新，新增了 DA 占用 gas 标量 (DA footprint gas scalar) 。

| 输入参数                 | 类型      | Calldata 字节 | 段   |
| -------------------- | ------- | ----------- | --- |
| {0x3db6be2b}         |         | 0-3         | n/a |
| baseFeeScalar        | uint32  | 4-7         | 1   |
| blobBaseFeeScalar    | uint32  | 8-11        |     |
| sequenceNumber       | uint64  | 12-19       |     |
| l1BlockTimestamp     | uint64  | 20-27       |     |
| l1BlockNumber        | uint64  | 28-35       |     |
| basefee              | uint256 | 36-67       | 2   |
| blobBaseFee          | uint256 | 68-99       | 3   |
| l1BlockHash          | bytes32 | 100-131     | 4   |
| batcherHash          | bytes32 | 132-163     | 5   |
| operatorFeeScalar    | uint32  | 164-167     | 6   |
| operatorFeeConstant  | uint64  | 168-175     |     |
| daFootprintGasScalar | uint16  | 176-177     |     |

请注意，与此前各版本的 L1 属性交易一样，第一个输入参数是函数选择器，
即 `keccak256("setL1BlockValuesJovian()")` 的前四个字节。

激活区块分为两种情况：

* 如果 Jovian 在创世时即已激活，则激活区块中不包含任何交易，
  因此无需考虑 L1 区块属性交易。
* 如果 Jovian 在创世之后激活，则必须使用 [`setL1BlockValuesIsthmus()`](../isthmus/l1-attributes) 方法。
  这是因为此时 L1 Block 合约尚未完成升级。

此后的每个 L2 区块都必须使用 `setL1BlockValuesJovian()` 方法。

使用该方法时，Jovian 之前的各项值会按 1:1 迁移，
同时该交易还会将 `daFootprintGasScalar` 设置为
[`SystemConfig`](/zh/specifications/base-protocol/consensus/derivation#system-configuration) 中的值。如果该值为 `0`，则使用默认值 `400`。
