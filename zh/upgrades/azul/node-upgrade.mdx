仅 `base-reth-node` (EL) 和 `base-consensus` (CL) 支持 Azul。运行 `op-node`、`op-geth`、`op-reth`、`nethermind` 或 `kona` 的节点必须按照以下说明完成迁移。

<Note>
  这两个客户端现均通过 [base/base](https://github.com/base/base/releases) 仓库发布。该仓库根目录下包含 `docker-compose.yml` 以及 `.env.mainnet` / `.env.sepolia` 模板，运营者以前需要从 `base/node` 获取这些文件。大部分配置已预先设好，也可通过环境变量覆盖——完整选项列表请参阅上述 `.env` 文件。

  `docker compose up` 会拉取已发布的 `ghcr.io/base/node` 镜像；传入 `--build` 可编译当前源码树，或设置 `NODE_TAG=vX.Y.Z` 锁定某个已发布的镜像版本，无需从源码构建。
</Note>

## 迁移执行层 {#migrating-execution-layer}

### 从 OP Reth 迁移 {#migrating-from-op-reth}

如果你已经通过运营者 compose 配置运行 OP Reth，只需更新到最新版本，节点便会自动使用 `base-reth-node`。现有的 `./reth-data` 目录完全兼容，无需重新同步或恢复快照。

1. 停止节点：

   ```bash
   docker compose down
   ```

2. 切换到 [base/base](https://github.com/base/base) 仓库 (运营者节点已不再通过 `base/node` 发布) ，并更新到最新版本：

   ```bash
   # 如果你之前克隆的是 base/node，请在同级目录下克隆 base/base，并将 .env 文件复制过去：
   git clone https://github.com/base/base.git
   cp ../node/.env.mainnet ./base/.env.mainnet   # 或 .env.sepolia

   # 如果你已在跟踪 base/base：
   git pull origin main
   ```

3. 启动节点：

   ```bash
   docker compose up
   ```

4. 验证客户端版本：`web3_clientVersion` 返回的版本字符串中应包含 `base` (例如 `reth/v1.11.3-.../base/v0.9.0`)

### 从其他客户端迁移 {#migrating-from-another-client}

`op-geth` 和 `nethermind` 已不再受支持。您需要使用 `base-reth-node` 从头开始部署。

1. 停止节点：

   ```bash
   docker compose down
   ```

2. 克隆或更新 [base/base](https://github.com/base/base)：

   ```bash
   git clone https://github.com/base/base.git
   # 如果已经克隆，则执行：
   git pull origin main
   ```

3. 删除旧的数据目录 (例如 `./geth-data` 或 `./nethermind-data`) 。

4. 根据需要编辑 `.env.mainnet` 或 `.env.sepolia` 文件。

5. 使用 [Reth 快照](/zh/specifications/node-operators/snapshots)进行引导，免去完整同步。

6. 启动节点：

   ```bash
   docker compose up
   ```

## 迁移共识层 {#migrating-consensus-layer}

只需更新环境变量，即可将 `op-node` 替换为 `base-consensus`。

1. 在 `.env` 文件中设置 `USE_BASE_CONSENSUS=true`。

2. 在 `.env` 文件中添加新的 `BASE_NODE_*` 环境变量 (参见下表) 。

3. 重启节点：

   ```bash
   docker compose up
   ```

4. 验证：
   * 查看共识日志：`docker compose logs -f node`
   * 确认同步状态：`optimism_syncStatus` 仍可正常使用

## 常见问题 {#faq}

* **我需要重新同步吗？** 如果您已经在运行 OP Reth，则无需重新同步。现有数据完全兼容。
* **如果我使用的是 `op-geth` 或 `nethermind` 怎么办？** 您需要切换到 `base-reth-node`。可以使用 [Reth 快照](/zh/specifications/node-operators/snapshots)快速完成节点初始化。
* **OP 命名空间下的 RPC 还能用吗？** 可以，所有现有 RPC 均继续受支持。
