当钱包授权重复扣款时，请使用已部署的 `SpendPermissionPaymentCollector`。由于每笔协议支付只能扣款一次，您的调度器仍需在每个计费周期创建新的 `PaymentInfo` 和唯一的 salt。

<Info>
  本指南中的支付流程基于 [Commerce Payments Protocol](https://github.com/base/commerce-payments)。
</Info>

## 扣取一个计费周期的费用 {#charge-one-billing-period}

收款方 (collector) 根据 `PaymentInfo` 重建支出权限 (spend permission) ：付款方即账户，收款方即支出方 (spender) ，代币和额度取自该笔支付，`preApprovalExpiry` 则作为权限的截止时间。将权限签名以及可选的 MagicSpend 提款请求编码为 `collectorData`。

提交协议扣款之前，请使用持久化的计费键，例如 `subscriptionId:periodStart`。

{/* sample: scheduled-charge-ts */}

```typescript TypeScript lines wrap expandable highlight={8-10,15,19-20,28}
export async function chargeSubscriptionPeriod(args: {
  paymentInfo: PaymentInfo;
  collectorData: Hex;
  billingKey: string;
  amount: bigint;
  store: BillingStore;
}) {
  if (!(await args.store.reserveOnce(args.billingKey))) {
    throw new Error("Billing period was already submitted");
  }
  const simulation = await publicClient.simulateContract({
    account,
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "charge",
    args: [
      args.paymentInfo,
      args.amount,
      SPEND_PERMISSION_PAYMENT_COLLECTOR,
      args.collectorData,
      0n,
      zeroAddress,
    ],
  });
  const hash = await walletClient.writeContract(simulation.request);
  const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Scheduled charge reverted");
  await args.store.complete(args.billingKey, hash);
  return receipt;
}
```

扣款成功后会触发 `PaymentCharged` 事件，并为该计费周期生成协议层面的 `refundableAmount`。

<Check>
  请在同一个持久化工作流中记录计费键、`paymentInfoHash`、扣款交易、金额以及支出权限的使用情况。
</Check>

<Warning>
  [Commerce Payments Protocol](https://github.com/base/commerce-payments) 本身不提供调度器。请妥善保护 operator 密钥，串行执行重试，并且不要复用上一周期的 `PaymentInfo` 或 salt。
</Warning>
