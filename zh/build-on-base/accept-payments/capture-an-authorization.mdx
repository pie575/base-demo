当订单可以结算时，对授权执行扣款。运营方会将托管金额的全部或部分转给收款方和手续费收款方，无需再次向付款方收款。你可以一次性扣款全部金额；若结账后最终总额有变，也可以只扣款部分金额；还可以在订单分批发货时分多次增量扣款。

<Info>
  本指南中的支付流程基于 [Commerce Payments Protocol](https://github.com/base/commerce-payments)。
</Info>

## 检查与扣款 {#check-and-capture}

扣款前，请先读取 `paymentState(paymentInfoHash)`。扣款金额必须非零、不得超过 `capturableAmount`，且必须严格早于 `authorizationExpiry` 提交。

运营方需以原始代币单位提供 `feeAmount` 的绝对值。协议会依据 `PaymentInfo` 中存储的单次扣款 `minFeeBps` 和 `maxFeeBps` 对其进行校验。

{/* sample: usdc-capture-ts */}

```typescript TypeScript lines wrap expandable highlight={8-11,16-17}
export async function captureAuthorization(
  payment: StoredProtocolPayment,
  amount = payment.paymentInfo.maxAmount,
) {
  const [, capturableAmount] = await publicClient.readContract({
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "paymentState",
    args: [payment.paymentInfoHash],
  });
  if (amount > capturableAmount) throw new Error("Capture exceeds authorized amount");
  const simulation = await publicClient.simulateContract({
    account,
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "capture",
    args: [payment.paymentInfo, amount, 0n, zeroAddress],
  });
  const hash = await walletClient.writeContract(simulation.request);
  const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Payment capture reverted");
  return receipt;
}
```

扣款会使 `capturableAmount` 减少、`refundableAmount` 增加，两者的变动额均为同一笔总额。收款方实际收到的是总额扣除费用后的金额。

<Check>
  在将该履约增量标记为已结算之前，请确认已触发 `PaymentCaptured(paymentInfoHash, amount, feeAmount, feeReceiver)` 事件，且收款方收到的转账符合预期。
</Check>

## 部分扣款 {#capture-a-partial-amount}

<PaymentsDemo flow="partial" />

每次分批扣款时，只需向同一个 `capture` 调用传入较小的 `amount`。所有成功扣款的总额不得超过 `PaymentAuthorized.amount`，且每次扣款都会单独校验其费用上下限。剩余的预留额度在链上跟踪，无需自定义结账合约。

以一笔 100 USDC 的授权为例，扣款 64 USDC 后，还剩 36 USDC 可扣款，64 USDC 可退款。你可以继续扣款，也可以[作废剩余额度](/zh/build-on-base/accept-payments/void-an-authorization)。

<Check>
  每次扣款后，在其他 worker 推进订单之前，先将 `PaymentCaptured.amount` 与新的 `capturableAmount` 和 `refundableAmount` 进行核对。
</Check>

<Warning>
  费用上下限按每次扣款单独计算，且采用整数除法。对于小数位数较少的代币，将一笔结算拆分为多笔小额扣款可能会降低最低费用总额。如果这一点对你很重要，请在链下强制设定最低扣款金额。
</Warning>

## 扣款截止时间 {#capture-deadline}

<Warning>
  一旦到达 `authorizationExpiry`，将无法再执行扣款 (capture) ，付款方可以收回剩余余额。校验截止时间时，请以链上时间为准，而不要依赖应用服务器的时钟。
</Warning>
