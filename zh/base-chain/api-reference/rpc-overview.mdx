Base 提供一套完全兼容 EVM 的统一 JSON-RPC API，并分为两个性能层级。只需更换一个 URL 和一个区块标签，即可从 2 秒的区块确认切换到 200ms 的预确认。

## 网络 {#networks}

有关网络详情、RPC 端点和钱包设置，请参阅[连接到 Base](/base-chain/quickstart/connecting-to-base)。

<Note>
  Base 公共端点**仅支持 HTTP**，不支持 WebSocket RPC 连接 (`eth_subscribe`、`newHeads`、`logs`) 。如需使用 WebSocket，请从 [Builder Stack](/zh/get-started/builder-stack) 中选择支持 WebSocket 的提供商。
</Note>

## Flashblocks {#flashblocks}

所有 Base 公共端点均已启用 Flashblocks。所有标准 `eth_` 方法的用法完全不变，而 `pending` 区块标签对应的是当前**正在构建的预确认区块**。该区块约每 200ms 更新一次，每次都会加入一批由排序器排好序的新交易。

`eth_getBalance`、`eth_getStorageAt` 和 `eth_call` 等调用基于真实的排序器状态执行，最多可在区块封块前 1.8 秒获取结果，延迟低于一秒。

### Flashblocks API {#flashblocks-api}

用于在 Base 上获取亚秒级交易信号的预确认方法。借助这些方法，你可以在区块封块前最多约 1.8 秒读取状态、模拟交易包并以流式方式接收事件。

| 方法                                                                                               | 描述                   |
| ------------------------------------------------------------------------------------------------ | -------------------- |
| [eth&#95;simulateV1](/zh/base-chain/api-reference/flashblocks-api/eth_simulateV1)                   | 基于预确认状态模拟交易包         |
| [base&#95;transactionStatus](/zh/base-chain/api-reference/flashblocks-api/base_transactionStatus)   | 检查交易是否已被内存池接收        |
| [newFlashblockTransactions](/zh/base-chain/api-reference/flashblocks-api/newFlashblockTransactions) | 订阅单笔预确认交易            |
| [pendingLogs](/zh/base-chain/api-reference/flashblocks-api/pendingLogs)                             | 订阅预确认交易中经过筛选的日志      |
| [newFlashblocks](/zh/base-chain/api-reference/flashblocks-api/newFlashblocks)                       | 订阅完整的 Flashblock 负载流 |

### Debug API {#debug-api}

用于深度检查交易和重放区块的开发与调试工具。Debug 方法会重放交易，计算开销较大；[Builder Stack](/zh/get-started/builder-stack) 中各服务商对这些方法的支持情况和速率限制不尽相同。

| 方法                                                                                           | 描述                    |
| -------------------------------------------------------------------------------------------- | --------------------- |
| [debug&#95;traceTransaction](/zh/base-chain/api-reference/debug-api/debug_traceTransaction)     | 获取交易的完整 EVM 执行追踪      |
| [debug&#95;traceBlockByHash](/zh/base-chain/api-reference/debug-api/debug_traceBlockByHash)     | 按哈希获取区块内所有交易的 EVM 追踪  |
| [debug&#95;traceBlockByNumber](/zh/base-chain/api-reference/debug-api/debug_traceBlockByNumber) | 按区块号获取区块内所有交易的 EVM 追踪 |

## 请求与响应格式 {#request-response-format}

所有请求均使用 HTTP POST 方法，并设置 `Content-Type: application/json`。

| 字段        | 类型     | 说明          |              |
| :-------- | :----- | :---------- | ------------ |
| `jsonrpc` | string | 固定为 `"2.0"` |              |
| `method`  | string | RPC 方法名     |              |
| `params`  | array  | 按顺序排列的方法参数  |              |
| `id`      | number | string      | 标识符，响应中会原样返回 |

**请求：**

```json Request
{
  "jsonrpc": "2.0",
  "method": "eth_getBalance",
  "params": ["0x742d35Cc6634C0532925a3b8D4C9dD0b4f3BaEa", "pending"],
  "id": 1
}
```

**成功响应：**

```json Success Response
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": "0x1a055690d9db80000"
}
```

**错误响应：**

```json Error Response lines wrap expandable
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,
    "message": "Invalid params"
  }
}
```

## 错误码 {#error-codes}

| 代码       | 名称    | 描述                    |
| -------- | ----- | --------------------- |
| `-32700` | 解析错误  | JSON 无效               |
| `-32600` | 无效请求  | 不是有效的 JSON-RPC 2.0 对象 |
| `-32601` | 方法未找到 | 方法不存在或不可用             |
| `-32602` | 无效参数  | 方法参数无效                |
| `-32603` | 内部错误  | JSON-RPC 内部错误         |
| `-32000` | 服务器错误 | 节点特有的错误 (详见错误消息)      |

## 区块参数 {#block-parameters}

| 值             | 标准        | Flashblocks                               |
| ------------- | --------- | ----------------------------------------- |
| `"latest"`    | 最近封装的区块   | 最近封装的区块                                   |
| `"pending"`   | 未打包交易池状态  | **当前正在构建的 Flashblock (约 200ms 粒度)&#x20;**&#x20;|
| `"safe"`      | 最新的安全区块   | 最新的安全区块                                   |
| `"finalized"` | 最新的已终结区块  | 最新的已终结区块                                  |
| `"earliest"`  | 创世区块      | 创世区块                                      |
| `"0x<n>"`     | 按区块号指定的区块 | 按区块号指定的区块                                 |
