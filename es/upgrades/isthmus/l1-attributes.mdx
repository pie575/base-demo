## Descripción general {#overview}

La transacción de atributos de bloque de L1 se actualiza para incluir los parámetros de la tarifa del operador.

| Argumento de entrada | Tipo    | Bytes de calldata | Segmento |
| -------------------- | ------- | ----------------- | -------- |
| {0x098999be}         |         | 0-3               | n/a      |
| baseFeeScalar        | uint32  | 4-7               | 1        |
| blobBaseFeeScalar    | uint32  | 8-11              |          |
| sequenceNumber       | uint64  | 12-19             |          |
| l1BlockTimestamp     | uint64  | 20-27             |          |
| l1BlockNumber        | uint64  | 28-35             |          |
| basefee              | uint256 | 36-67             | 2        |
| blobBaseFee          | uint256 | 68-99             | 3        |
| l1BlockHash          | bytes32 | 100-131           | 4        |
| batcherHash          | bytes32 | 132-163           | 5        |
| operatorFeeScalar    | uint32  | 164-167           | 6        |
| operatorFeeConstant  | uint64  | 168-175           |          |

Tenga en cuenta que, al igual que en las versiones anteriores de la transacción de atributos de L1,
el primer argumento de entrada es el selector de función: los primeros cuatro bytes de `keccak256("setL1BlockValuesIsthmus()")`.

En el bloque de activación caben dos posibilidades:

* Si Isthmus está activo desde el génesis, el bloque de activación no contiene transacciones
  y, por lo tanto, no hay ninguna transacción de atributos de bloque de L1 que tener en cuenta.
* Si Isthmus se activa después del génesis, se debe usar el método [`setL1BlockValuesEcotone()`](../ecotone/l1-attributes),
  ya que el contrato L1 Block todavía no se habrá actualizado.

En cada bloque de L2 posterior, se debe usar el método `setL1BlockValuesIsthmus()`.

Al usar este método, los valores previos a Isthmus se migran 1:1
y la transacción también asigna a los siguientes atributos nuevos los valores
del contrato [`SystemConfig`](/es/specifications/base-protocol/consensus/derivation#system-configuration):

* `operatorFeeScalar`
* `operatorFeeConstant`
