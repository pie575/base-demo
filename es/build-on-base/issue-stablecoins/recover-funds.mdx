En ocasiones necesitará retirar el saldo de una cuenta que ha bloqueado: un titular que perdió sus claves, una orden judicial o una retención por sanciones. `seizeWithMemo` transfiere los tokens del titular a una cuenta de custodia con una sola llamada de administrador. No se trata de una quema ni de una acuñación: `totalSupply` no cambia, el memo registra onchain su referencia del caso y el token emite un evento `Seized` específico que los auditores y los indexadores pueden rastrear.

## Antes de empezar {#before-you-start}

Necesitas todo lo siguiente:

* Una stablecoin B20 que administres, con `DEFAULT_ADMIN_ROLE` para poder otorgar roles y adjuntar políticas.
* Una cuenta que llamará a `seizeWithMemo` (la cuenta que realiza la incautación). Otórgale `SEIZE_ROLE`.
* El ID de la política de lista de bloqueo que creaste en [Bloquear una cuenta](/es/build-on-base/issue-stablecoins/block-an-account), con el titular ya incluido en ella.
* Un destino de custodia distinto de la dirección cero que no sea el titular ni la propia dirección del token; normalmente, tu tesorería.
* `SEIZE` sin pausar. `pause([SEIZE])` bloquea todas las incautaciones hasta que se ejecute `unpause([SEIZE])`. Pausar `TRANSFER`, `MINT` o `BURN` no afecta a la incautación.

Tres controles determinan si se puede ejecutar una incautación, y se comprueban en este orden:

| Control                 | Qué comprueba                                                                                                           | Valor predeterminado si no se configura                                       |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `SEIZE_ROLE`            | El llamador puede incautar.                                                                                             | Nadie puede incautar.                                                         |
| `SEIZE_EXEMPT_POLICY`   | El titular (`from`) **no** está autorizado según la política adjunta. Una cuenta autorizada está exenta de incautación. | Todas las cuentas están autorizadas, por lo que no se puede incautar a nadie. |
| `SEIZE_RECEIVER_POLICY` | El destino (`to`) está autorizado según la política adjunta.                                                            | Se permite cualquier destino.                                                 |

`SEIZE_EXEMPT_POLICY` funciona a la inversa que los ámbitos de transferencia. Adjunta una **lista de bloqueo**: las cuentas de la lista no están autorizadas, por lo que pasan a ser incautables, y todas las demás siguen exentas. No adjuntes una lista de permitidos ni `ALWAYS_BLOCK`; una lista de permitidos vacía no autoriza a nadie, lo que haría incautables a todos los titulares.

La incautación no tiene en cuenta los ámbitos de transferencia. Bloquear a un titular en `TRANSFER_SENDER_POLICY` congela sus transferencias salientes, pero no lo vuelve incautable hasta que esa misma lista de bloqueo (u otra) se adjunte a `SEIZE_EXEMPT_POLICY`.

## Incautar y verificar el saldo bloqueado {#seize-and-verify-the-blocked-balance}

Primero, otorga `SEIZE_ROLE` a la cuenta que realizará la incautación. Esta configuración solo se hace una vez por token:

```solidity Grant SEIZE_ROLE
token.grantRole(token.SEIZE_ROLE(), seizer);
```

A continuación, asocia tu lista de bloqueo a `SEIZE_EXEMPT_POLICY` y mueve el saldo:

<CodeGroup>
  {/* sample: stablecoin-recover-ts */}

  ```typescript TypeScript lines wrap expandable highlight={10,11}
  import { parseUnits, stringToHex, type Address } from "viem";
  import { publicClient } from "../../shared/clients.js";
  import { b20Abi, scope } from "../abi.js";
  import { sendContract } from "../write.js";

  export async function recoverBlockedFunds(token: Address, blocklistId: bigint, blocked: Address, treasury: Address) {
    const amount = parseUnits("50", 6);
    const memo = stringToHex("legal-hold-2026-118", { size: 32 });
    await sendContract({ address: token, abi: b20Abi, functionName: "updatePolicy", args: [scope("SEIZE_EXEMPT_POLICY"), blocklistId] });
    await sendContract({ address: token, abi: b20Abi, functionName: "seizeWithMemo", args: [blocked, treasury, amount, memo] });
    const balance = await publicClient.readContract({ address: token, abi: b20Abi, functionName: "balanceOf", args: [treasury] });
    if (balance < amount) throw new Error("Seized balance did not reach the treasury");
  }
  ```

  {/* sample: stablecoin-recover-solidity */}

  ```solidity Solidity lines wrap expandable highlight={2,3}
  function recoverStablecoin(address token, uint64 blocklistId, address blocked, address treasury) public {
      IB20(token).updatePolicy(B20Constants.SEIZE_EXEMPT_POLICY, blocklistId);
      IB20(token).seizeWithMemo(blocked, treasury, 50e6, bytes32("legal-hold-2026-118"));
      require(IB20(token).balanceOf(treasury) >= 50e6, "treasury not funded");
  }
  ```

  {/* sample: stablecoin-recover-cli */}

  ```bash CLI lines wrap expandable highlight={1,3}
  base-cast send "$TOKEN_ADDRESS" "updatePolicy(bytes32,uint64)" "$(base-cast keccak SEIZE_EXEMPT_POLICY)" "$BLOCKLIST_ID" \
    --rpc-url "$RPC_URL" --private-key "$PRIVATE_KEY"
  base-cast send "$TOKEN_ADDRESS" "seizeWithMemo(address,address,uint256,bytes32)" "$BLOCKED" "$TREASURY" 50000000 \
    "$(base-cast format-bytes32-string legal-hold-2026-118)" --rpc-url "$RPC_URL" --private-key "$PRIVATE_KEY"
  base-cast call "$TOKEN_ADDRESS" "balanceOf(address)(uint256)" "$TREASURY" --rpc-url "$RPC_URL"
  ```
</CodeGroup>

Al asociar la política se emite `PolicyUpdated`, y el cambio surte efecto a partir del siguiente `seizeWithMemo`. Puedes asociar varios tokens a la misma lista de bloqueo. La incautación en sí emite, en este orden, `Transfer(from, to, amount)`, `Memo(caller, memo)` y `Seized(caller, from, to, amount)`.

Una vez en la tesorería, el saldo pasa a ser un saldo normal. Puedes reenviarlo a la nueva dirección del titular con un `transfer` normal o retenerlo mientras el caso siga abierto.

Si además quieres restringir los destinos, crea una lista de permitidos que incluya la tesorería y asóciala a `SEIZE_RECEIVER_POLICY`. Omite este paso si te sirve cualquier dirección de custodia; si el ámbito no está configurado, ya se permite cualquier `to`.

<Check>
  `Seized(caller, from, to, amount)` aparece en la transacción. El saldo bloqueado disminuye, el saldo de la tesorería aumenta en la misma cantidad y `totalSupply` no cambia.
</Check>

## Errores comunes {#common-errors}

Estos errores aparecen en el mismo orden en que `seizeWithMemo` los comprueba.

| Error                                                  | Causa                                                                                                                                      | Solución                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `ContractPaused(SEIZE)`                                | `SEIZE` está en pausa.                                                                                                                     | Llama a `unpause` con `PausableFeature.SEIZE`.                                |
| `AccessControlUnauthorizedAccount(caller, SEIZE_ROLE)` | El llamador no tiene `SEIZE_ROLE`.                                                                                                         | Otorga `SEIZE_ROLE` a la cuenta que realiza la incautación.                   |
| `InvalidReceiver(to)`                                  | `to` es `address(0)`, la propia dirección del token o la misma que `from`.                                                                 | Usa una dirección de custodia distinta de `from` y distinta de cero.          |
| `InvalidSender(from)`                                  | `from` es `address(0)`.                                                                                                                    | Pasa la dirección del titular.                                                |
| `AccountNotSeizable(from)`                             | `from` sigue autorizada según `SEIZE_EXEMPT_POLICY`. La ranura no está configurada o el titular no figura en la lista de bloqueo asociada. | Asocia una lista de bloqueo a `SEIZE_EXEMPT_POLICY` y añade `from` a ella.    |
| `PolicyForbids(SEIZE_RECEIVER_POLICY, policyId)`       | `to` no está autorizada según `SEIZE_RECEIVER_POLICY`.                                                                                     | Añade `to` a la lista de receptores permitidos o restablece el ámbito a `0`. |
| `InsufficientBalance(from, balance, amount)`           | `from` tiene menos que `amount`.                                                                                                           | Incauta `balanceOf(from)` o una cantidad menor.                               |
| `PolicyNotFound(policyId)`                             | `updatePolicy` recibió un ID que no existe en el registro.                                                                                 | Crea primero la política y luego asocia el ID devuelto.                       |
| `Unauthorized()`                                       | Una cuenta que no es administradora llamó a `updateBlocklist` o `updateAllowlist`.                                                         | Realiza la llamada como `policyAdmin` de la política.                         |

Un saldo que ya se encuentra en la propia dirección del token todavía puede recuperarse: `seizeWithMemo(address(token), treasury, amount, memo)` está permitido. Lo que no se permite es incautar *hacia* la dirección del token.

<Warning>
  Usa esta vía en lugar de la solución alternativa obsoleta `burnBlocked`, que quema el saldo bloqueado y acuña otro de reemplazo. Ese método reduce y luego restaura `totalSupply`, no emite ningún evento `Seized` y obliga a la conciliación a trabajar con dos transacciones sin relación entre sí en lugar de un único movimiento rastreable.
</Warning>
