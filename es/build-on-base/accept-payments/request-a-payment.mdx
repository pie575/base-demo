Solicita un pago inmediato con la operación `charge`. El pagador aprueba las condiciones del pago y el cobro de los tokens; después, tu operador cobra, liquida y registra el importe como reembolsable en una sola transacción.

<Info>
  El flujo de pago de esta guía se basa en el [Commerce Payments Protocol](https://github.com/base/commerce-payments).
</Info>

## Cobrar y verificar el pago {#charge-and-verify-the-payment}

El fixture completo crea un `PaymentInfo` único, deriva su hash independiente del pagador y pide al pagador que firme una autorización `ReceiveWithAuthorization` de ERC-3009 para el colector desplegado. A continuación, el operador envía `charge`.

| Colector         | Ideal para                                                                  |
| ---------------- | --------------------------------------------------------------------------- |
| ERC-3009         | USDC y otros tokens con autorizaciones de transferencia nativas             |
| Permit2          | Compatibilidad más amplia con ERC-20 una vez que el pagador aprueba Permit2 |
| Preaprobación    | Allowance estándar de ERC-20 más una preaprobación específica para el pago  |
| Permiso de gasto | Flujos de cobro recurrente basados en billeteras                            |

B20 y otros tokens ERC-20 pueden usar Permit2 o el colector de preaprobación siempre que sus políticas de transferencia permitan participar al colector, al almacén de tokens del operador, al receptor y al receptor de comisiones.

{/* sample: usdc-accept-ts */}

```typescript TypeScript lines wrap expandable highlight={2,7,11-12}
export async function requestPayment(receiver: Address, orderId: string) {
  const payment = await prepareErc3009Payment(receiver, orderId, "5.00");
  const simulation = await publicClient.simulateContract({
    account,
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "charge",
    args: [
      payment.paymentInfo,
      payment.paymentInfo.maxAmount,
      ERC3009_PAYMENT_COLLECTOR,
      payment.collectorData,
      0n,
      zeroAddress,
    ],
  });
  const hash = await operatorWallet.writeContract(simulation.request);
  const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Payment charge reverted");
  return { hash, paymentInfoHash: payment.paymentInfoHash };
}
```

El protocolo envía `amount - feeAmount` a `paymentInfo.receiver`, envía la comisión por separado e incrementa `refundableAmount` en el importe total cobrado.

<Check>
  Confirma `PaymentCharged`, comprueba que su `paymentInfoHash` corresponda al pedido y reclama el evento de forma atómica antes de completar el pedido.
</Check>

<Warning>
  La firma del pagador no equivale a la liquidación. Solo un recibo de `charge` exitoso demuestra que el cobro y la distribución se han completado. Mantén `maxFeeBps` en un rango acotado y fija `feeReceiver`, salvo que tu operador necesite sustituir a un destinatario incluido en una lista de denegación.
</Warning>
