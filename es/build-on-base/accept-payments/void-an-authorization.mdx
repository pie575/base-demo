Cierra una autorización que no vayas a capturar. El operador puede llamar a `void` en cualquier momento para devolver todos los fondos capturables restantes. Si el operador deja de estar activo, el pagador puede llamar a `reclaim` a partir del momento indicado en `authorizationExpiry`.

<Info>
  El flujo de pago de esta guía se basa en el [Commerce Payments Protocol](https://github.com/base/commerce-payments).
</Info>

| `reclaim(paymentInfo)` | Pagador   | A partir de `authorizationExpiry`                     |

## Anular la autorización restante {#void-the-remaining-authorization}

`void` devuelve el `capturableAmount` completo; no existe ninguna operación de anulación parcial. Primero captura el importe final cumplido y, después, anula el resto.

{/* sample: usdc-void-ts */}

```typescript TypeScript lines wrap expandable highlight={5,8,13-14}
export async function voidAuthorization(payment: StoredProtocolPayment) {
  const [, capturableAmount] = await publicClient.readContract({
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "paymentState",
    args: [payment.paymentInfoHash],
  });
  if (capturableAmount === 0n) throw new Error("Authorization has no remaining funds");
  const simulation = await publicClient.simulateContract({
    account,
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "void",
    args: [payment.paymentInfo],
  });
  const hash = await walletClient.writeContract(simulation.request);
  const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Payment void reverted");
  return receipt;
}
```

Tanto `void` como `reclaim` establecen `capturableAmount` en cero y dejan intacto cualquier `refundableAmount` capturado previamente.

<Check>
  Verifica `PaymentVoided` o `PaymentReclaimed` y comprueba que su importe coincida con el saldo capturable justo antes de la devolución.
</Check>

<Warning>
  Una vez vencida la autorización, el operador y el pagador pueden competir por devolver el mismo remanente mediante `void` o `reclaim`. Una de las llamadas se ejecuta correctamente y la otra se revierte con `ZeroAuthorization`; procesa cualquiera de los dos eventos de forma idempotente como la devolución definitiva de la autorización.
</Warning>
