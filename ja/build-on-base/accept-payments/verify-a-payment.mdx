ウォレットの署名、送信済みのトランザクションハッシュ、クライアントの状態を根拠に注文を履行してはいけません。確定済みの `AuthCaptureEscrow` イベントをデコードし、その `paymentInfoHash` を注文と照合したうえで、各決済が永続ストレージ上で一度だけ処理済みとして記録されるようにしてください。

<Info>
  このガイドの決済フローは [Commerce Payments Protocol](https://github.com/base/commerce-payments) に基づいています。
</Info>

## プロトコル決済を検証する {#verify-a-protocol-settlement}

v1.1.0 のエスクローアドレスと ABI は必ず組み合わせて使用してください。`PaymentCharged` イベントと `PaymentCaptured` イベントには、絶対値で表された `uint256 feeAmount` が含まれます。v1.0 のイベントは、フィールドの型もイベントトピックもこれとは異なります。

{/* sample: verify-token-payment-ts */}

```typescript Backend lines wrap expandable highlight={12,18-19,22-23}
export async function verifyPayment(args: {
  hash: Hash;
  paymentInfoHash: Hash;
  orderId: string;
  store: PaymentStore;
}) {
  const receipt = await publicClient.waitForTransactionReceipt({ hash: args.hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Payment transaction reverted");
  const events = parseEventLogs({
    abi: authCaptureEscrowAbi,
    logs: receipt.logs.filter(
      (log) => log.address.toLowerCase() === AUTH_CAPTURE_ESCROW.toLowerCase(),
    ),
    strict: true,
  });
  const settlement = events.find(
    (event) =>
      (event.eventName === "PaymentCharged" || event.eventName === "PaymentCaptured") &&
      event.args.paymentInfoHash === args.paymentInfoHash,
  );
  if (!settlement) throw new Error("Expected protocol settlement was not found");
  if (!(await args.store.claimOnce(args.paymentInfoHash, args.orderId))) {
    throw new Error("Payment was already used");
  }
  return settlement;
}
```

`PaymentAuthorized` と `PaymentCharged` には完全な `PaymentInfo` が含まれます。それ以降のライフサイクルイベントにはハッシュしか含まれないため、注文作成時に保存した不変の条件と突き合わせて結合してください。

<Check>
  チェーン、エスクローアドレス、支払いハッシュ、操作、金額、手数料がすべて想定どおりである、最初に確定したイベントだけがフルフィルメントに進みます。
</Check>

<Warning>
  `claimOnce` はデータベースの一意性制約を使用し、フルフィルメントと同じ永続的なワークフローの中で実行する必要があります。プロセスローカルな `Set` では、再起動をまたいだリプレイや複数ワーカー間でのリプレイを防ぐことはできません。
</Warning>

フルフィルメントの価値と取り消し可能性に見合った確認深度 (confirmation depth) を選択してください。詳しくは[トランザクションのファイナリティ](/ja/specifications/transactions/transaction-finality)を参照してください。
