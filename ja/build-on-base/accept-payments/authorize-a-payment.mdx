フルフィルメント (商品・サービスの提供) がチェックアウト後に行われる場合は、支払いを認可します。プロトコルでの認可が成功すると、トークンは即座にオペレーターのエスクローストアへ移動します。そのため、後で行うキャプチャは、支払者がウォレットに資金を残しているかどうかに左右されません。

<Info>
  このガイドの支払いフローは [Commerce Payments Protocol](https://github.com/base/commerce-payments) に基づいています。
</Info>

</Warning>

## 支払いを認可して保存する {#authorize-and-store-the-payment}

オペレーター、支払者、受取人、トークン、最大金額、順序付けられた3つの有効期限タイムスタンプ、手数料の上下限、手数料受取人、一意のソルトを含む、不変の `PaymentInfo` を1つ構築します。以降のすべての操作でこの構造体のハッシュが再計算されるため、構造体は一切変更せずにそのまま保存してください。

フィクスチャでは ERC-3009 のコレクター署名を用意し、`paymentInfo.operator` から認可を送信します。

{/* sample: usdc-authorize-ts */}

```typescript TypeScript lines wrap expandable highlight={6,11,15-16}
export async function authorizePayment(
  merchant: Address,
  orderId: string,
  amount: string,
) {
  const payment = await prepareErc3009Payment(merchant, orderId, amount);
  const simulation = await publicClient.simulateContract({
    account,
    address: AUTH_CAPTURE_ESCROW,
    abi: authCaptureEscrowAbi,
    functionName: "authorize",
    args: [
      payment.paymentInfo,
      payment.paymentInfo.maxAmount,
      ERC3009_PAYMENT_COLLECTOR,
      payment.collectorData,
    ],
  });
  const hash = await walletClient.writeContract(simulation.request);
  const receipt = await publicClient.waitForTransactionReceipt({ hash, confirmations: 2 });
  if (receipt.status !== "success") throw new Error("Payment authorization reverted");
  return { ...payment, authorizationHash: hash };
}
```

| 状態フィールド               | 認可後の値             |
| --------------------- | ----------------- |
| `hasCollectedPayment` | 恒久的に `true`       |
| `capturableAmount`    | エスクローに保持された認可済み金額 |
| `refundableAmount`    | キャプチャされるまで `0`    |

<Check>
  `paymentInfoHash`、すべての支払い条件、コレクター、認可トランザクション、および `PaymentAuthorized.amount` を注文に紐づけて永続化してください。
</Check>

<Warning>
  支払いの回収は一度しか行えません。void や reclaim 後の再試行も含め、チェックアウトを試行するたびに、暗号学的に安全な新しいランダムソルトを使用してください。
</Warning>
