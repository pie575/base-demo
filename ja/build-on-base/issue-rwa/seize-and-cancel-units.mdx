保有者が適格要件を満たさなくなった場合、裁判所が没収を命じた場合、またはポジションを解消する必要がある場合は、`seizeWithMemo` でユニットを保管用アカウントに移し、その後の扱いを決定します。このガイドでは、ユニットを発行体のトレジャリーに差し押さえ、`burnWithMemo` で消却します。この最初のステップは、凍結と再発行にもそのまま使えます。その場合は、差し押さえた後にトレジャリーから新しいアドレスへ転送します。

## 始める前に {#before-you-start}

以下のすべてが必要です。

* 自身が管理する B20 Asset。ロールの付与やポリシーの設定を行えるよう、`DEFAULT_ADMIN_ROLE` を保持している必要があります。
* `seizeWithMemo` と `burnWithMemo` を呼び出すアカウント。このアカウントに `SEIZE_ROLE` と `BURN_ROLE` を付与してください。[Create an Asset Token](/ja/build-on-base/issue-rwa/create-an-asset-token) のウォークスルーではファクトリー呼び出し時にロールを付与しています。まだ付与していない場合は、この 2 つを追加してください。
* 対象の保有者が登録された、Policy Registry 内のブロックリストポリシー。[保有資格者を制限する](/ja/build-on-base/issue-rwa/restrict-eligible-holders) のように許可リストで保有資格を制限している場合、その許可リストから保有者を削除すると転送は凍結されますが、差し押さえ可能には**なりません**。差し押さえは専用のスコープを参照します。
* `SEIZE` と `BURN` が一時停止されていないこと。`TRANSFER` や `MINT` を一時停止しても、差し押さえは引き続き実行できます。

差し押さえスコープの仕組み:

| スコープ                    | チェック対象のアカウント | 実行される条件                    | 未設定時のデフォルト                    |
| ----------------------- | ------------ | -------------------------- | ----------------------------- |
| `SEIZE_EXEMPT_POLICY`   | `from`       | `isAuthorized` が **false** | 全員が認可されているため、誰も差し押さえ対象になりません。 |
| `SEIZE_RECEIVER_POLICY` | `to`         | `isAuthorized` が **true**  | 任意の送付先が許可されます。                |

保有者のチェックは判定が反転しているため、`SEIZE_EXEMPT_POLICY` には**ブロックリスト**を設定してください。リストに含まれるアカウントは未認可となるため差し押さえ可能になり、それ以外の保有者はすべて対象外のままです。このスコープに許可リストや `ALWAYS_BLOCK` を設定しないでください。空の許可リストは誰も認可しないため、すべての保有者が差し押さえ対象になってしまいます。

## 差し押さえ、消却、検証 {#seize-cancel-and-verify}

ロールの付与は、トークンごとに一度だけ行います。

```solidity Grant SEIZE_ROLE and BURN_ROLE
asset.grantRole(asset.SEIZE_ROLE(), operator);
asset.grantRole(asset.BURN_ROLE(), operator);
```

次に、ブロックリストをアタッチし、呼び出し元自身のアカウントに差し押さえてから、そこからバーンします。

<CodeGroup>
  {/* sample: stock-seize-ts */}

  ```typescript TypeScript lines wrap expandable highlight={10,11,12}
  import { parseUnits, stringToHex, type Address } from "viem";
  import { account, publicClient } from "../../shared/clients.js";
  import { b20Abi, scope } from "../abi.js";
  import { sendContract } from "../write.js";

  export async function seizeAndCancelUnits(token: Address, blocklistId: bigint, holder: Address) {
    const amount = parseUnits("100", 6);
    const memo = stringToHex("cancel-2026-07", { size: 32 });
    await sendContract({ address: token, abi: b20Abi, functionName: "updatePolicy", args: [scope("SEIZE_EXEMPT_POLICY"), blocklistId] });
    await sendContract({ address: token, abi: b20Abi, functionName: "seizeWithMemo", args: [holder, account.address, amount, memo] });
    await sendContract({ address: token, abi: b20Abi, functionName: "burnWithMemo", args: [amount, memo] });
    return publicClient.readContract({ address: token, abi: b20Abi, functionName: "totalSupply" });
  }
  ```

  {/* sample: stock-seize-solidity */}

  ```solidity Solidity lines wrap expandable highlight={2,3,4}
  function seizeAndCancelUnits(address token, uint64 blocklistId, address holder) public {
      IB20(token).updatePolicy(B20Constants.SEIZE_EXEMPT_POLICY, blocklistId);
      IB20(token).seizeWithMemo(holder, address(this), 100e6, bytes32("cancel-2026-07"));
      IB20(token).burnWithMemo(100e6, bytes32("cancel-2026-07"));
  }
  ```

  {/* sample: stock-seize-cli */}

  ```bash CLI lines wrap expandable highlight={1,3,5}
  base-cast send "$TOKEN_ADDRESS" "updatePolicy(bytes32,uint64)" "$(base-cast keccak SEIZE_EXEMPT_POLICY)" "$BLOCKLIST_ID" \
    --rpc-url "$RPC_URL" --private-key "$PRIVATE_KEY"
  base-cast send "$TOKEN_ADDRESS" "seizeWithMemo(address,address,uint256,bytes32)" "$HOLDER" "$TREASURY" 100000000 \
    "$(base-cast format-bytes32-string cancel-2026-07)" --rpc-url "$RPC_URL" --private-key "$PRIVATE_KEY"
  base-cast send "$TOKEN_ADDRESS" "burnWithMemo(uint256,bytes32)" 100000000 "$(base-cast format-bytes32-string cancel-2026-07)" \
    --rpc-url "$RPC_URL" --private-key "$PRIVATE_KEY"
  base-cast call "$TOKEN_ADDRESS" "totalSupply()(uint256)" --rpc-url "$RPC_URL"
  ```
</CodeGroup>

差し押さえでは、`Transfer(holder, treasury, amount)`、`Memo(caller, memo)`、`Seized(caller, holder, treasury, amount)` の順にイベントが発行されます。この時点では `totalSupply` は変わりません。続くバーンでは `Transfer(treasury, address(0), amount)` と `Memo` が発行され、`totalSupply` が減少します。両方の呼び出しで同じ memo を使えば、照合時に 2 つのステップを 1 つの案件として紐付けられます。

`burnWithMemo` は呼び出し元自身の残高をバーンするため、差し押さえを実行するアカウントを送付先にも指定するか、あらかじめトレジャリーからバーン実行者へ転送しておく必要があります。後で再発行する場合、その受取人も通常の転送と同様に `TRANSFER_RECEIVER_POLICY` を満たす必要があります。

保有者やインデクサーに消却を告知するには、`burnWithMemo` を `announce` でラップします。詳しくは[保有者に変更を告知する](/ja/build-on-base/issue-rwa/announce-a-distribution)を参照してください。

<Check>
  最初のトランザクションに `Seized` が記録され、保有者の残高が 100 EXM 減少します。バーン後は、`totalSupply` も 100 EXM 減少します。
</Check>

## よくあるエラー {#common-errors}

以下のエラーは `seizeWithMemo` がチェックする順に並んでおり、最後にバーン時のエラーを記載しています。

| エラー                                                    | 原因                                                                                  | 対処法                                                                          |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `ContractPaused(SEIZE)`                                | `SEIZE` が一時停止されています。                                                                | `PausableFeature.SEIZE` を指定して `unpause` を呼び出します。                             |
| `AccessControlUnauthorizedAccount(caller, SEIZE_ROLE)` | 呼び出し元が `SEIZE_ROLE` を保持していません。                                                      | `SEIZE_ROLE` を付与します。                                                         |
| `InvalidReceiver(to)`                                  | `to` が `address(0)`、トークン自身のアドレス、または `from` と同じアドレスです。                               | これらとは異なる、ゼロ以外の保管用アドレスを使用します。                                                 |
| `InvalidSender(from)`                                  | `from` が `address(0)` です。                                                           | 保有者のアドレスを渡します。                                                               |
| `AccountNotSeizable(from)`                             | `from` が `SEIZE_EXEMPT_POLICY` で依然として認可されています。スロットが未設定か、保有者が紐付けられたブロックリストに含まれていません。 | `SEIZE_EXEMPT_POLICY` にブロックリストを紐付け、`from` を追加します。転送許可リストから保有者を削除するだけでは不十分です。 |
| `PolicyForbids(SEIZE_RECEIVER_POLICY, policyId)`       | `to` が `SEIZE_RECEIVER_POLICY` で認可されていません。                                          | `to` を受取人許可リストに追加するか、スコープを `0` に戻します。                                        |
| `InsufficientBalance(from, balance, amount)`           | `from` の保有量が `amount` に満たません。                                                       | `balanceOf(from)` 以下の量を差し押さえます。                                              |
| `AccessControlUnauthorizedAccount(caller, BURN_ROLE)`  | バーンの実行者が `BURN_ROLE` を保持していません。                                                     | `BURN_ROLE` を付与します。                                                          |
| `ContractPaused(BURN)`                                 | `BURN` が一時停止されています。                                                                 | `PausableFeature.BURN` を指定して `unpause` を呼び出します。                              |
| `PolicyNotFound(policyId)`                             | `updatePolicy` に渡された ID がセンチネル値ではなく、レジストリにも存在しません。                                  | 先にポリシーを作成し、返された ID を紐付けます。                                                   |
| `Unauthorized()`                                       | 管理者以外が `updateBlocklist` または `updateAllowlist` を呼び出しました。                            | ポリシーの `policyAdmin` として呼び出します。                                               |

トークン自身のアドレスにすでにある残高は回収できます。`seizeWithMemo(address(token), treasury, amount, memo)` は許可されています。ただし、トークンのアドレス*を送り先として*差し押さえることはできません。

<Warning>
  `burnBlocked` は非推奨です。この関数は `TRANSFER_SENDER_POLICY` で拒否された保有者からユニットを直接破棄し、`Seized` イベントを発行しません。そのため、ユニットが償還ではなく差し押さえによって取り上げられたことを示すオンチェーン記録が残りません。差し押さえてからバーンする方法を推奨します。
</Warning>
