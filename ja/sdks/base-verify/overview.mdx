Base Verify を使用すると、ユーザーは認証情報をアプリケーションに開示することなく、検証済みアカウントを自身が管理していることを証明できます。Sybil 耐性の追加、複数のウォレットをまたいだ重複参加の防止、検証済みの属性に基づくアクションの制限などに活用できます。

## 各インテグレーションの違い {#how-the-integrations-differ}

|                 | ソーシャルアカウントを検証する                 | オンチェーンでユーザーを検証する                      |
| --------------- | -------------------------------------- | ----------------------------------------- |
| 検証の実施場所         | アプリケーションのバックエンド                        | スマートコントラクト                                |
| 利用する Base の機能   | Base Verify REST API                   | Base Verify REST API とオンチェーンコントラクト        |
| 返される結果          | 検証トークンと属性情報                            | 署名付きの `identityHash`、有効期限、署名              |
| 主な用途            | アクセス制限付きのアプリケーション体験、報酬、バックエンドで管理するクレーム | コントラクトレベルのクレーム、デポジット、ミント、投票などのオンチェーンアクション |
| アプリケーションのバックエンド | 必須                                     | クレーム時には不要                                 |

どちらのインテグレーションでも、リクエスト元がウォレットを管理していることを証明するために、ウォレットで署名した SIWE メッセージを使用します。Base Verify はリクエストされたプロバイダーまたはポリシーを評価し、選択したフローに必要な検証データのみを返します。
