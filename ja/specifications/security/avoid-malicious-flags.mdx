アプリを信頼できるものとして認識してもらい、悪意あるものとして判定されないようにするには、ベストプラクティスを押さえておくことが重要です。ここでは、安全でコンプライアンスに準拠したアプリを開発当初から構築する方法を簡単に紹介します。

## 1. スマートコントラクトを検証し、リスクを低減する {#1-verify-and-reduce-the-risk-of-your-smart-contract}

* **スマートコントラクトの検証**: コントラクトのソースコードが、[Builder Stack](/ja/get-started/builder-stack) に掲載されているブロックエクスプローラーで検証・公開されていることを確認してください。たとえば、[Etherscan](https://etherscan.io/verifyContract) や [Basescan](https://basescan.org/verifyContract) の「Verify Contract」からコントラクトを検証できます。
* **ユーザー資金のリスクを最小限に抑える**: ユーザー資金がリスクにさらされる範囲を最小限に抑えるよう、コントラクトを設計してください。効率的な設計を採用し、不要なリスクを減らしましょう。たとえば、トランザクションの実行に必要な最小限の金額のみを要求するようにします。

## 2. 検証リクエストを送信する {#2-submit-a-verification-request}

スマートコントラクトの検証が完了したら、[検証リクエストの送信](https://report.blockaid.io/)も検討してください。この手順を行うことで、エコシステム内の信頼できる情報源によって、アプリが安全かつ検証済みであると認識されやすくなります。

## 3. アプリのベストプラクティスに従う {#3-follow-app-best-practices}

* **地域を問わないアクセス**: 特定の地域や国からアプリにアクセスできなくなるようなジオブロッキングやアクセス制限は避けてください。法的またはコンプライアンス上の理由で制限が必要な場合は、検証リクエストの提出時にその旨を記載できます。
* **一貫した動作**: UI を急に変更したり、説明なく変更したりすることは避けてください。ユーザーがアプリの信頼性に不安を抱く原因になります。
* **透明性のあるオンチェーン操作**: アプリのオンチェーン操作がわかりやすく、UI 上の操作と一致していることを確認してください。たとえば、「Mint」ボタンを押したら、明確に mint トランザクションが発行されるようにする必要があります。
* **標準的なサインイン方法**: WalletConnect / Coinbase Wallet SDK や一般的なブラウザ拡張機能ウォレットなど、ユーザーがサインインに使う標準的な接続方法をすべて用意してください。
* **コントラクトの監査**: 信頼できる監査会社にコントラクトの監査を依頼してください。監査レポートを公開し、ユーザーが簡単に見つけられるよう参照リンクを掲載してください。監査を受けていれば、スマートコントラクトの安全性を高めるために一歩踏み込んだ対策を講じていることを示せます。

これらの推奨事項に従うことで、アプリが悪意あるものとして判定される可能性を大幅に減らし、ユーザーにとって安全で信頼できる環境を築くことができます。

***

**それでも問題が解決しない場合**
Coinbase Wallet では、アプリが誤って検知される (誤検知) ことがあります。誤検知を避けるため、上記の推奨事項を実施済みであることを確認してください。それでもアプリが疑わしいもの、または悪意あるものとして判定される場合は、[Blockaid に報告してください](https://report.blockaid.io/mistake)。
