---
title: スループットと制限
description: Base におけるガスリミットおよびスループット関連のネットワークパラメータ。
---

Base のスループットは、ガスリミット、データ可用性のスループット、手数料市場のパラメータ、エンドポイントの制限によって制約されます。トランザクションごとに消費するガスとデータの量は異なるため、あらゆるワークロードに共通する単一の TPS (秒間トランザクション数) の値はありません。

Base はこれまでに 5,000 TPS を超えるバーストを複数回にわたって維持しており、チェーンのスケーリングに伴ってスループットは今後も向上していきます。詳しくは [Introducing Base Azul](https://blog.base.dev/introducing-base-azul) を参照してください。

## 現在の上限 {#current-limits}

| 上限                   | 値                                           |
| -------------------- | ------------------------------------------- |
| ブロック全体のガス予算          | 約400M gas                                   |
| 最初の Flashblock のガス予算 | 約40M gas                                    |
| トランザクションあたりのガス上限     | 16,777,216 gas (2^24)                       |
| デポジットトランザクションの上限     | 1つの L1 ブロックに含めることができる最大ガス (20,000,000 gas)  |

ブロック全体のガス予算は、ブロックの構築中に各 Flashblock へ分配されます。Flashblock 1 はブロックガス上限の 1/10、Flashblock 2 は 2/10 を使用でき、以降も同様に段階的に増え、Flashblock 10 で上限全体を使用できるようになります。これがトランザクションの順序付けに与える影響については、[トランザクションの順序付け](/ja/specifications/transactions/transaction-ordering#flashblocks)を参照してください。

## Flashblock のパフォーマンス {#flashblock-performance}

Flashblocks は約 200ms ごとにブロックの増分更新をストリーミング配信し、標準の 2 秒のブロック時間内で、アプリに 1 秒未満のプレコンファメーションを提供します。

| 指標                       | 値         |
| ------------------------ | --------- |
| Flashblock のビルド時間 (P50)  | 約 10ms    |
| プレコンファメーションのレイテンシ        | 約 200ms   |
| フルブロックのブロック時間            | 2 秒       |
| 1 ブロックあたりの Flashblock 数  | 10        |
| リオーグ率                    | &lt; 0.1% |

リオーグの処理方法やその他のよくある質問については、[Flashblocks リファレンス](/ja/specifications/flashblocks)を参照してください。

## トランザクションあたりのガス上限 {#per-transaction-gas-maximum}

[Azul ハードフォーク](/ja/upgrades/azul/exec-engine#transaction-gas-limit-cap)以降、Base は [EIP-7825](https://eips.ethereum.org/EIPS/eip-7825) に基づき、トランザクションあたりのガス上限として **16,777,216 gas (2^24)** をプロトコルレベルで適用しています。この値を超えるガスリミットを指定したトランザクションは、**ブロック検証時に拒否されます**。この場合、`eth_sendTransaction` または `eth_sendRawTransaction` は JSON-RPC エラー (例: `exceeds maximum per-transaction gas limit`) を返します。

<Note>
  デポジットトランザクションはこの上限の対象外です。ただし、L1 ブロックに含めることができる最大ガス量 (20,000,000 gas) による制限を受けます。
</Note>

スマートコントラクトウォレットのバンドラー運用者は、バンドルのサイズがこの上限に収まるようにシステムを設定する必要があります。

## 手数料パラメータ {#fee-parameters}

需要が利用可能な容量に近づいたとき、トランザクションがブロックに取り込まれるかどうかは手数料によって決まるため、手数料は実質的なスループットに影響します。

| パラメータ                   | 現在の値                        |
| ----------------------- | --------------------------- |
| 最小基本手数料                 | 5,000,000 wei (0.005 gwei)  |
| EIP-1559 弾力性係数          | 6                           |
| EIP-1559 分母             | 125                         |
| ブロックあたりの L2 基本手数料の最大変動率 | 4%                          |

L2 実行手数料や L1 セキュリティ手数料など、Base のトランザクション手数料の構成については、[ネットワーク手数料](/ja/specifications/transactions/network-fees)を参照してください。

## データ可用性のスループット {#data-availability-throughput}

Base のトランザクションデータは、データ可用性を確保するために Ethereum に送信されます。データ可用性のスループットが逼迫した場合、シーケンサーは batcher が追いつくまで L2 のトランザクションスループットを制限することがあります。

DA スロットリング中は、高い優先手数料を設定したトランザクションであっても遅延する可能性があります。スロットリングを考慮した優先手数料の見積もりを算出する RPC エンドポイントはありません。トランザクション送信への影響については、[トランザクションのトラブルシューティング](/ja/specifications/transactions/troubleshooting-transactions#priority-fee-too-low)を参照してください。

## エンドポイントの制限 {#endpoint-limits}

パブリックエンドポイントにはレート制限があり、本番環境のトラフィックには適していません。ホスト型の RPC プロバイダーでも、1 秒あたりのリクエスト数、コンピュートユニット、利用可能なメソッド、アーカイブデータ、WebSocket サブスクリプションなどに制限が設けられている場合があります。

エンドポイントの制限によって Base プロトコル自体の処理能力が変わることはありませんが、アプリ、ウォレット、インデクサー、監視システムにとっては実質的なボトルネックになり得ます。本番環境で利用する場合は、[Builder Stack](/ja/get-started/builder-stack) から RPC プロバイダーを選ぶか、[Base ノードを運用](/ja/specifications/node-operators/run-a-node)してください。
