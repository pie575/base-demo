## Base のネットワーク手数料の仕組み {#how-do-network-fees-on-base-work}

Base のすべてのトランザクションには、L2 (実行) 手数料と L1
(セキュリティ) 手数料という2種類のコストがかかります。L2 手数料は L2 上でトランザクションを実行するためのコストで、
L1 手数料はトランザクションを L1 に公開するための推定コストです。
通常は、L1 セキュリティ手数料のほうが L2 実行手数料よりも高くなります。

L1 手数料は、L1 上のトランザクション量に応じて変動します。トランザクションの
タイミングを調整できる場合は、L1 のガス代が安い時間帯 (週末など) に
トランザクションを送信することでコストを抑えられます。

同様に、L2 手数料も L2 に送信されるトランザクションの数に応じて
増減します。この調整メカニズムは
L1 と同じ方式で実装されています。詳しくは
[Coinbase の EIP-1559 ガイド](https://help.coinbase.com/en/coinbase/getting-started/crypto-education/eip-1559)をご覧ください。

Base における手数料計算の詳細については、
[ネットワーク手数料の仕様](/ja/specifications/base-protocol/execution/predeploys#gaspriceoracle)を参照してください。

## 最低ベースフィー {#minimum-base-fee}

[Jovian upgrade]の一環として、Baseは最低ベースフィーを導入しました。この機能はL2のベースフィーに下限を設けるもので、ネットワークのアクティビティが少ない期間にベースフィーが極端に低い水準まで下がるのを防ぎます。

Base Mainnetの最低ベースフィーは5,000,000 wei (0.005 gwei) です。この値は、チェーンへの影響に関するデータを収集しながら、定期的に調整される場合があります。参考までに、ETH価格が$2000の場合、最低ベースフィーが0.005 gweiであれば、一般的な200,000 gasのトランザクションのコストは約$0.002になります。

### 利点 {#benefits}

* **トランザクションの迅速な取り込み**: 従来は、アクティビティの低下によってベースフィーが極めて低い水準まで下がっていると、需要が急増した際に、滞留したトランザクションを解消できる水準まで手数料が上がるまで、長時間にわたって混雑が続くことがありました。最低ベースフィーを設けることで、ユーザーが手動でプライオリティフィーを調整しなくても、通常はトランザクションがより迅速にブロックに取り込まれるようになります。
* **手数料の予測可能性の向上**: 通常時、ベースフィーは最低値またはその付近で推移し、混雑時には最低値を超えて上昇します。これにより、サージプライシング(需要に応じた変動料金制)に似た、より予測しやすい手数料体系が実現します。
* **スパムの防止**: 手数料が極端に低いと、ネットワークに価値をもたらさないスパムトランザクションを助長しかねません。最低ベースフィーは、正当な利用に対しては手頃な手数料を維持しつつ、こうした活動をコスト面で抑止する効果があります。

### 現在の設定 {#current-configuration}

| ネットワーク       | 最低ベースフィー                    |
| ------------ | --------------------------- |
| Base Mainnet | 5,000,000 wei (0.005 gwei)  |
| Base Sepolia | 5,000,000 wei (0.005 gwei)  |

最低ベースフィーをはじめとするネットワークパラメータの変更履歴については、[設定変更履歴](/ja/base-chain/network-information/configuration-changelog)を参照してください。

## EIP-1559 手数料パラメータ {#eip-1559-fee-parameters}

Base は独自の EIP-1559 実装を採用しています。この実装により、ネットワークの需要に応じて L2 のベースフィーがどのように調整されるかが制御されます。この挙動は、次の 2 つの主要なパラメータによって決まります。

### Elasticity Multiplier {#elasticity-multiplier}

**Elasticity Multiplier**(弾力性乗数)は、目標ガス使用量を基準として、ブロックの最大ガス容量を定めるパラメータです。弾力性が6の場合、ブロックには目標ガスの最大6倍までを含めることができるため、ネットワークは突発的な需要の急増にも対応できます。

### ベースフィー変更分母 {#base-fee-change-denominator}

**ベースフィー変更分母** (Base Fee Change Denominator) は、ベースフィーの調整速度を制御します。分母が大きいほど、手数料はゆっくりと段階的に変化します。分母を125にすると、より小さい値の場合に比べてベースフィーは滑らかに変化します。

### 最大変化率 {#maximum-rate-of-change}

ブロックあたりのベースフィーの最大変化率は、次の式で計算されます。

**ブロックあたりの最大増加率 = (Elasticity - 1) / 分母 (Denominator)&#x20;**

現在のパラメーター (Elasticity = 6、Denominator = 125) では、次のようになります。

* ブロックあたりの最大増加率：(6 - 1) / 125 = **4%**
* ベースフィーが2倍になるまでの最短時間：18ブロック × 2秒 = **36秒**

このように段階的に調整することで、トラフィックが急増しても手数料が極端に変動するのを防ぎつつ、需要が持続する場合にはネットワークが対応できるようになっています。

### 現在の設定 {#current-configuration-2}

| ネットワーク       | Elasticity | 分母  | ブロックあたりの最大変化率 |
| ------------ | ---------- | --- | ------------- |
| Base Mainnet | 6          | 125 | 4%            |
| Base Sepolia | 6          | 125 | 4%            |

## L1 手数料 のクエリ {#querying-the-l1-fee}

`0x420000000000000000000000000000000000000F` にある **GasPriceOracle** プリデプロイ ([コントラクトアドレス](/ja/specifications/reference/base-contracts)を参照) を使うと、トランザクションに署名して送信する前に、L1 手数料 の構成要素をプログラムで見積もることができます。

| メソッド                                 | 戻り値                                          |
| ------------------------------------ | -------------------------------------------- |
| `getL1Fee(bytes)`                    | 完全にシリアライズ (RLP エンコード) されたトランザクションの正確な L1 手数料 |
| `getL1FeeUpperBound(uint256 txSize)` | トランザクションのおおよそのバイト長から算出した L1 手数料 の上限見積もり      |
| `l1BaseFee()`                        | Base から見た現在の Ethereum L1 base fee            |
| `blobBaseFee()`                      | 現在の EIP-4844 blob base fee                   |
| `baseFeeScalar()`                    | L1 base fee の構成要素に適用されるスカラー                  |
| `blobBaseFeeScalar()`                | blob base fee の構成要素に適用されるスカラー                |

トランザクションの構築が完了する前に手早く見積もりたい場合は、`getL1FeeUpperBound` を使用してください。署名前に正確な値を得たい場合は、完全にシリアライズしたトランザクションを渡して `getL1Fee` を呼び出してください。
