---
title: トランザクションのファイナリティ
description: Base におけるトランザクションのファイナリティの詳細。
---

ファイナリティとは、Base に送信されたトランザクションが不可逆になる時点を指します。ファイナリティに達したトランザクションは、ロールバックされたり失われたりしないことが保証されます。

ファイナリティの仕組みは、Base L2 の状態を変更する通常のトランザクションと、Base L2 から Ethereum L1 へ資金を引き出すトランザクションとで異なります。

<Note>
  **7 日間の待機が必要なのは、Base から Ethereum へ資金を引き出すトランザクションのみです。** スワップや送金など、Base 内での通常のトランザクションでは、7 日間待つ必要は *ありません*。
</Note>

## Base L2トランザクションのファイナリティ {#finality-for-base-l2-transactions}

ここでは、Base上のトランザクションのファイナリティについて説明します。ただし、BaseからEthereum L1へ資金を移動する出金トランザクションは対象外です。

Base上のトランザクションのファイナリティは、一定時間待てば得られるという単一のものではありません。時間の経過に応じて4つのステージがあり、ステージが進むごとにセキュリティ保証が強くなります。

<Frame>
  ![Base上のトランザクションファイナリティのステージを示す図](/images/transaction-finality/base-tx-finality.jpg)
</Frame>

<Steps>
  <Step title="Flashblockへの取り込み：約200ms" titleSize="h3">
    約200ms後、トランザクションはBaseのsequencerによって事前承認ブロック (Flashblock) に取り込まれます。

    <Accordion title="リオルグの確率は0.001%未満">
      * Flashblocksでリオルグが発生する確率は0.001%未満です
      * リオルグの履歴は[公開統計ページ](https://base.org/stats)で確認できます。
    </Accordion>
  </Step>

  <Step title="L2ブロックへの取り込み：約2秒" titleSize="h3">
    約2秒後、sequencerはトランザクションをL2ブロックに組み込み、バリデーターノードに配信します。

    <Accordion title="リオルグの確率はほぼ0%">
      * これまでにリオルグが発生したBase L2ブロックは1つだけで、トランザクション全体の0.0000003%に相当します。データは[こちらで確認できます](https://base.blockscout.com/blocks?tab=reorgs)
    </Accordion>
  </Step>

  <Step title="L1バッチへの取り込み：約2分" titleSize="h3">
    約2分後、トランザクションを含むBaseのバッチがEthereumに投稿されます。

    <Accordion title="リオルグの確率は実質0%">
      * Ethereum L1にバッチとして投稿されたL2ブロックでリオルグが発生したことは、これまで一度もありません。
      * **Ethereum L1でリオルグが発生しても、Base L2チェーンをリオルグする必要はありません。** sequencerとバリデーターノードはEthereumの最新ブロックから設定可能な遅延を保っているため、通常のL1リオルグの影響は受けません。Ethereumで大規模なリオルグが発生した場合でも、Baseはシーケンス済みのL2ブロックを変更することなく、L1上にバッチデータを再投稿できます。
    </Accordion>
  </Step>

  <Step title="L1バッチのファイナリティ：約20分" titleSize="h3">
    トランザクションを含むEthereum L1バッチが、2エポック (64 L1ブロック) 以上前のものになった段階です。

    <Accordion title="リオルグの確率は実質0%">
      * L1バッチのファイナリティに達したL2ブロックは、Ethereumのファイナライズ済みブロックと同様にリオルグから保護されており、事実上取り消すことはできません。
    </Accordion>
  </Step>
</Steps>

## 出金トランザクションのファイナリティ {#finality-for-withdrawal-transactions}

ここでは、資金を Base から Ethereum へ移動するトランザクションのファイナリティについて説明します。

**Ethereum への出金に限り、ファイナライズまで 7 日間待機しなければ、Ethereum L1 上のアドレスに資金は解放されません。** この仕組みにより、Base の Fault Proof システムは、Base にブリッジされた資金に対して極めて高いセキュリティを保証できます。

<Accordion title="7 日間に何が起こるのか？">
  トランザクションによって Base から Ethereum への出金が開始されると、資金は Base 上のアカウント残高から差し引かれます。その後、パーミッションレスな「プロポーザー」が、この出金が Base に含まれていることの証明を Ethereum に提出する必要があります。

  しかし、Ethereum と Base は別々のブロックチェーンであるため、Ethereum は Base で何が起きたかをネイティブに確認できません。そこで、パーミッションレスな「チャレンジャー」が、悪意があると判断したプロポーザルに異議を申し立てられる 7 日間の猶予期間が設けられています。7 日以内にチャレンジがなければ、出金はファイナライズ済みの出力ルートに対して証明でき、L1 の受取人に解放されます。一方、チャレンジが行われた場合は、プロポーザーとチャレンジャーの間で Fault Dispute Game と呼ばれるゲームが行われます。このゲームでは、段階的に増加するボンドを預け入れる必要があり、最終的に勝者が決まります。プロポーザーが勝てば、出力ルートはファイナライズされ、出金の証明に使用できるようになります (これにより L1 で出金が解放されます) 。チャレンジャーが勝てば、その出力プロポーザルは無効になります。

  このシステムは、誠実な参加者が 1 者いるだけで安全性を維持できます。Base は常に誠実なプロポーザーとチャレンジャーを運用します。

  注: チャレンジャーがディスピュートゲームに勝った場合でも、L2 チェーンの状態がリオルグされることはありません。その出力プロポーザルが無効としてマークされ、それに対して証明された出金はファイナライズできなくなります。これらの出金は、別の有効な出力ルートに対して証明し直す必要があります。
</Accordion>

## FAQ {#faq}

<AccordionGroup>
  <Accordion title="Ethereumでリオルグが発生した場合、Baseでもリオルグは発生しますか？">
    ほとんどの場合、発生しません。BaseはL2チェーンの進行を止めることなく、バッチデータをEthereumに透過的に再送信できます。
  </Accordion>

  <Accordion title="デポジットトランザクションのファイナライズにはどのくらい時間がかかりますか？">
    Ethereum L1からBaseへ資金を移動するトランザクションはEthereum上で開始する必要があり、通常は3分以内にBaseのsequencerによって取り込まれます。
  </Accordion>

  <Accordion title="チャレンジャーがディスピュートゲームに勝利した場合、L2チェーンはリオルグしますか？">
    いいえ。チャレンジされた出力プロポーザルは無効としてマークされ、その出力ルートを使用したアクションはすべて無効になります。具体的には、この出力ルートに対して証明済みのBaseからL1への出金は、別の有効な出力ルートに対して改めて証明する必要があります。
  </Accordion>
</AccordionGroup>
