このガイドでは、公式の [Base Node Docker セットアップ](https://github.com/base/base)を使って Base ノードをセットアップ・運用する際によく発生する問題を取り上げ、その診断方法と解決手順を説明します。

## 一般的なトラブルシューティング手順 {#general-troubleshooting-steps}

個別の問題を詳しく調べる前に、まずは次の一般的な手順を試してみてください。多くの場合、これで解決の手がかりが得られます。

1. **コンテナのログを確認する**: 通常、これが最も多くの情報を得られる手順です。`docker compose logs -f <service_name>` を使用すると、特定のコンテナのログをリアルタイムで表示できます。
   * L2 クライアント (Reth): `docker compose logs -f execution`
   * ロールアップノード: `docker compose logs -f node`。エラー、警告、繰り返し出力されるメッセージがないか確認してください。

2. **コンテナの状態を確認する**: `docker compose ps` を実行して、該当する Docker コンテナが稼働していることを確認します。コンテナが頻繁に再起動している場合や停止している場合は、そのログを確認してください。

3. **リソース使用状況を確認する**: サーバーの CPU、RAM、ディスク I/O、ネットワークの使用状況を監視します。パフォーマンスの問題は、リソース不足が原因であることがよくあります。`htop`、`iostat`、`iftop` などのツールが役立ちます。

4. **RPC エンドポイントを検証する**: `curl` を使用して、L2 クライアントの RPC エンドポイントが応答しているかを確認します ([ノードの実行](/ja/specifications/node-operators/run-a-node#running-a-node)を参照) 。あわせて、L1 エンドポイントが正しく設定され、ノードサーバーからアクセスできることも確認してください。

5. **L1 ノードを確認する**: 設定した L1 ノード (実行層およびコンセンサス層) が完全に同期済みで、正常に動作しており、アクセス可能であることを確認します。L1 ノードに問題があると、L2 ノードは正しく同期できません。

## よくある問題と解決策 {#common-issues-and-solutions}

### セットアップと設定に関する問題 {#setup-configuration-issues}

* **問題**: Docker コマンド (`docker compose up ...`) が失敗する
  * **確認**: Docker と Docker Compose がインストールされ、Docker デーモンが起動していますか？
  * **確認**: 正しいディレクトリ (`docker-compose.yml` を含む、クローンした `base/base` ディレクトリ) にいますか？
  * **確認**: コマンドに構文エラー (例: `NETWORK_ENV` のスペルミス) はありませんか？

* **問題**: コンテナが起動せず、ログに `.env` ファイルや環境変数に関するエラーが表示される。
  * **確認**: 正しい `.env` ファイル (`.env.mainnet` または `.env.sepolia`) に L1 エンドポイント (`BASE_NODE_L1_ETH_RPC`、`BASE_NODE_L1_BEACON`) を正しく設定しましたか？
  * **確認**: `.env` ファイルで `RETH_CHAIN` と `RETH_SEQUENCER_HTTP` が正しく設定されていますか？

* **問題**: `base-consensus` と実行クライアント間で、JWT シークレットまたは認証に関するエラーが発生する。
  * **確認**: 内容を十分に理解している場合を除き、`BASE_NODE_L2_ENGINE_AUTH` 変数や JWT ファイルパス (`$BASE_NODE_L2_ENGINE_AUTH`) を手動で変更していないか確認してください。通常は `docker-compose` のセットアップによって自動的に処理されます。

* **問題**: データボリューム (`./reth-data`) に関する権限エラーが発生する。
  * **確認**: `docker compose` を実行するユーザーに、`base/base` リポジトリをクローンしたディレクトリ (または設定した `HOST_DATA_DIR`) への書き込み権限があることを確認してください。Docker が `./reth-data` に書き込める必要があります。Docker コマンドを `sudo` で実行すると、後から権限の問題が生じる場合があります。`docker` グループに追加した非 root ユーザーで実行してみてください。

### 同期に関する問題 {#syncing-problems}

* **問題**: ノードが同期を開始しない、または停止しているように見える (ブロック高が増加しない) 。
  * **確認**: `base-consensus` のログ。L1 エンドポイントや実行クライアントへの接続エラーが出ていないか確認します。
  * **確認**: 実行クライアントのログ。Engine API (ポート `8551`) 経由での `base-consensus` への接続エラーや P2P の問題が出ていないか確認します。
  * **確認**: L1 ノードの稼働状態と同期状況。L1 ノードにアクセスでき、完全に同期していますか？
  * **確認**: システム時刻。サーバーの時計が正確に同期されていることを確認してください (`ntp` または `chrony` を使用) 。時刻が大きくずれていると、P2P の問題が発生する可能性があります。

* **問題**: 同期が非常に遅い。
  * **確認**: ハードウェア仕様。[ノードのパフォーマンス](/ja/specifications/node-operators/performance-tuning)ガイドに記載されている推奨仕様 (特に RAM と **NVMe SSD**) を満たしていますか？ディスク I/O がボトルネックになっているケースがよくあります。
  * **確認**: L1 ノードのパフォーマンス。L1 の RPC エンドポイントは速やかに応答していますか？L1 ノードが遅いと、L2 の同期も遅くなります。
  * **確認**: ネットワーク接続の品質と帯域幅。
  * **確認**: `base-consensus` と実行クライアントのログに、パフォーマンスに関する警告やエラーが出ていないか。

* **問題**: `optimism_syncStatus` (`base-consensus` のポート `7545`) で大きな時間差やエラーが表示される。
  * **対処**: ステータスを確認した時刻前後のロールアップノードと L2 実行クライアントの両方のログを調べ、根本原因 (例: L1 接続の問題、L2 クライアントの問題) を特定します。

* **問題**: トランザクション送信時に `Error: nonce has already been used` が発生する。
  * **原因**: ノードがまだチェーンの先頭まで完全に同期していません。
  * **対処**: ノードの同期が完了するまで待ちます。`optimism_syncStatus` またはログで進捗を監視してください。

### パフォーマンスの問題 {#performance-issues}

* **問題**: CPU、RAM、またはディスク I/O の使用率が高い。
  * **確認事項**: ハードウェアの仕様が [ノードのパフォーマンス](/ja/specifications/node-operators/performance-tuning) の推奨要件を満たしているか確認し、必要に応じてアップグレードしてください。ローカルの NVMe SSD は非常に重要です。
  * **確認事項**: クライアントログを確認し、具体的なエラーやボトルネックが発生していないか調べてください。

### スナップショット復元の問題 {#snapshot-restoration-problems}

正しい手順については、[Snapshots](/ja/specifications/node-operators/snapshots) ガイドを参照してください。

* **問題**: `wget` コマンドが失敗する、またはダウンロードしたスナップショットが破損している。
  * **確認**: ネットワーク接続。
  * **確認**: ディスクの空き容量。
  * **対処**: ダウンロードを再試行してください。また、ダウンロード URL が正しいことを確認してください。

* **問題**: `tar` による展開が失敗する。
  * **確認**: ダウンロードしたファイルの整合性 (破損していないか) 。
  * **確認**: ディスクの空き容量 (展開にはダウンロードよりもはるかに多くの容量が必要です) 。
  * **確認**: `tar` コマンドの構文。

* **問題**: スナップショットの復元後にノードが起動せず、ログにデータベースエラーやファイル欠落が表示される。
  * **確認**: データディレクトリを変更する *前に* ノードを停止 (`docker compose down`) しましたか？
  * **確認**: スナップショットデータを展開・移動する前に、古いデータディレクトリの *中身* (`./reth-data/*`) を削除しましたか？
  * **確認**: スナップショットデータは正しく移動されていますか？チェーンデータは、入れ子になったサブフォルダ (例: `./reth-data/reth/...`) ではなく、`./reth-data` の直下に配置する必要があります。フォルダ構成を確認してください。

* **問題**: ダウンロードまたは展開の途中でディスク容量が不足した。
  * **対処**: ディスク容量を空けるか、より大きなボリュームを用意してください。必要なストレージ容量は次の計算式で見積もれます:
    ```
    (2 * chain_size + snapshot_size + 20% buffer)  
    ```

### ネットワーク / 接続の問題 {#networking-connectivity-issues}

* **問題**: RPC/WS 接続が拒否される (例: `localhost:8545` への `curl` が失敗する) 。
  * **確認**: L2 クライアントのコンテナは実行中ですか (`docker compose ps`) ？
  * **確認**: 正しいポートを使用していますか (デフォルトでは HTTP は `8545`、WS は `8546`) ？
  * **確認**: L2 クライアントのログを確認してください。RPC サーバーの起動に失敗していませんか？
  * **確認**:  (Docker ネットワーク内からの) 外部接続を許可するため、クライアントの設定/エントリポイントで `--http.addr` および `--ws.addr` フラグが `0.0.0.0` に設定されていますか？

* **問題**: ノードのピア数が少ない、またはどのピアにも接続できない。
  * **確認**: ファイアウォールでイングレスポート `30303` (TCP/UDP) と `9222` (Reth discv5 用の TCP/UDP) が開放されているか。
  * **確認**: アウトバウンド通信用にイグレスポート `30301` (TCP/UDP) と `9200` (UDP) が開放されているか。これらのポートは Base のブートノードへの接続に必要です。これらのポートへのアウトバウンド接続がブロックされていると、イングレスのルールにかかわらず、ノードはピア探索を開始できず、ピアを 1 つも見つけられません。
  * **確認**: ノードのログに P2P エラーが出ていないか。
  * **対処**: NAT 配下にある場合は、`.env` ファイルの `ADDITIONAL_ARGS` で `--nat=extip:<your-ip>` フラグを設定してください ([ネットワーク](/ja/specifications/node-operators/run-a-node#networking)を参照) 。

* **問題**: ログにポートの競合が報告される、または `docker compose up` が失敗する。
  * **確認**: ホスト上の他のサービスがデフォルトのポート (`8545`、`8546`、`8551`、`6060`、`7545`、`30303`) を使用していませんか？次のコマンドで確認できます。
    ```bash
    sudo lsof -i -P -n | grep LISTEN
    sudo netstat -tulpn | grep LISTEN
    ```
  * **対処**: 競合しているサービスを停止するか、`docker-compose.yml` の `ports` セクションを編集し、必要に応じて `.env` ファイル内の関連する環境変数 (`$RPC_PORT`、`$WS_PORT` など) を更新して、Base ノードのコンテナが使用するポートを変更してください。

## さらにサポートが必要な場合 {#getting-further-help}

このガイドの手順を実行しても問題が解決しない場合は、コミュニティにサポートを求めてください。

* **Discord**: [Base Discord](https://discord.gg/buildonbase) に参加し、`🛠｜node-operators` チャンネルに投稿してください。投稿の際は、セットアップの詳細、問題の内容、関連するログを記載してください。
* **GitHub**: [base/base リポジトリの issue](https://github.com/base/base/issues) を確認してください。バグの可能性がある場合は、新しい issue を作成してください。
