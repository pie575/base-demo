このガイドでは、Base ノードのパフォーマンスを最適化するために推奨されるハードウェア、クライアントソフトウェア、および設定について説明します。

## ハードウェア {#hardware}

Base ノードを高いパフォーマンスで運用するには、十分なハードウェアが必要です。最低限、以下のスペックを推奨します。

1. シングルコア性能に優れた最新のマルチコア (8 コア以上) CPU
2. 32 GB 以上の RAM (64 GB を推奨)
3. ローカル接続の NVMe SSD ドライブ。RAID 0 構成にするとパフォーマンスが向上する場合があります。
4. 次の計算式で求められる十分なストレージ容量:

```
  (2 × [現在のチェーンサイズ] + [スナップショットサイズ] + 20% のバッファ)
```

これは、チェーンデータの増加分とスナップショットの復元に必要な容量を見込んだ値です。現在のチェーンサイズについては [Base Stats](https://base.org/stats) を、スナップショットのサイズについては Base Snapshots(https://snapshots.base.org) を参照してください。

<Note>
  Amazon Elastic Block Store (EBS) を利用する場合は、十分なディスク読み取り速度を確保して初期同期中のレイテンシ問題を防ぐため、io2 Block Express ボリュームの使用を推奨します。ただし、**最適なパフォーマンスを得るには、ネットワークストレージではなくローカル接続の NVMe SSD を使用することを強く推奨します。**
</Note>

### 本番環境のハードウェア例 {#production-hardware-examples}

Base の本番ノードでは、以下のハードウェア仕様を使用しています。

* **Reth アーカイブノード:**
  * インスタンス: AWS `i7i.12xlarge` 以上
  * ストレージ: すべてのローカル NVMe ドライブ (`/dev/nvme*`) で構成した RAID 0
  * ファイルシステム: ext4

## 初期同期 {#initial-sync}

最新の[スナップショット](/ja/specifications/node-operators/snapshots)を使用すると、ノードの初期同期にかかる時間を大幅に短縮できます。

## クライアントソフトウェア {#client-software}

[Base Node](https://github.com/base/base) リポジトリには、各種クライアント実装を実行するための現行の安定版設定と手順が含まれています。

現在、Base ノードの実行において最もパフォーマンスに優れたクライアントは Reth です。今後の最適化も主に Reth を中心に進められます。詳しくは [Scaling Base with Reth](https://blog.base.dev/scaling-base-with-reth) をご覧ください。
