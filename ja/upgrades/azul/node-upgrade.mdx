Azul に対応しているのは `base-reth-node` (EL) と `base-consensus` (CL) のみです。`op-node`、`op-geth`、`op-reth`、`nethermind`、`kona` のいずれかを実行しているノードは、以下の手順に従って移行する必要があります。

<Note>
  両クライアントは現在、[base/base](https://github.com/base/base/releases) リポジトリで公開されています。このリポジトリには、これまでオペレーターが `base/node` から取得していたルートの `docker-compose.yml` と、`.env.mainnet` / `.env.sepolia` テンプレートが含まれています。ほとんどの設定は構成済みで、環境変数で上書きできます。指定可能なオプションの一覧は、これらの `.env` ファイルを参照してください。

  `docker compose up` を実行すると、公開済みの `ghcr.io/base/node` イメージが取得されます。現在のソースツリーをコンパイルする場合は `--build` を指定してください。ソースからビルドせずに特定のリリース済みイメージに固定する場合は、`NODE_TAG=vX.Y.Z` を設定します。
</Note>

## 実行レイヤーの移行 {#migrating-execution-layer}

### OP Reth からの移行 {#migrating-from-op-reth}

オペレーター用の compose セットアップですでに OP Reth を実行している場合は、最新バージョンに更新するだけで、ノードが自動的に `base-reth-node` を使用するようになります。既存の `./reth-data` ディレクトリは完全な互換性があるため、再同期やスナップショットの復元は必要ありません。

1. ノードを停止します:

   ```bash
   docker compose down
   ```

2. [base/base](https://github.com/base/base) に切り替え (オペレーターノードは `base/node` からは公開されなくなりました) 、最新バージョンに更新します:

   ```bash
   # 以前に base/node をクローンしていた場合は、同じ階層に base/base をクローンし、.env ファイルをコピーします:
   git clone https://github.com/base/base.git
   cp ../node/.env.mainnet ./base/.env.mainnet   # または .env.sepolia

   # すでに base/base を追跡している場合:
   git pull origin main
   ```

3. ノードを起動します:

   ```bash
   docker compose up
   ```

4. クライアントのバージョンを確認します: `web3_clientVersion` のバージョン文字列に `base` が含まれていれば問題ありません (例: `reth/v1.11.3-.../base/v0.9.0`)

### 他のクライアントからの移行 {#migrating-from-another-client}

`op-geth` と `nethermind` はサポートが終了しました。`base-reth-node` を使用して一からセットアップし直す必要があります。

1. ノードを停止します。

   ```bash
   docker compose down
   ```

2. [base/base](https://github.com/base/base) をクローンするか、最新の状態に更新します。

   ```bash
   git clone https://github.com/base/base.git
   # すでにクローン済みの場合:
   git pull origin main
   ```

3. 古いデータディレクトリ (例: `./geth-data` や `./nethermind-data`) を削除します。

4. 必要に応じて `.env.mainnet` または `.env.sepolia` ファイルを編集します。

5. フル同期を避けるため、[Reth スナップショット](/ja/specifications/node-operators/snapshots)からブートストラップします。

6. ノードを起動します。

   ```bash
   docker compose up
   ```

## コンセンサスレイヤーの移行 {#migrating-consensus-layer}

環境変数を更新して、`op-node` を `base-consensus` に置き換えます。

1. `.env` ファイルで `USE_BASE_CONSENSUS=true` を設定します。

2. `.env` ファイルに新しい `BASE_NODE_*` 環境変数を設定します (下表を参照) 。

3. ノードを再起動します：

   ```bash
   docker compose up
   ```

4. 動作を確認します：
   * コンセンサスのログを確認します：`docker compose logs -f node`
   * 同期ステータスを確認します：`optimism_syncStatus` が引き続き動作することを確認してください

## FAQ {#faq}

* **再同期は必要ですか？** すでに OP Reth を実行している場合は不要です。既存のデータとの互換性があります。
* **`op-geth` または `nethermind` を使用している場合はどうすればよいですか？** `base-reth-node` に切り替える必要があります。[Reth スナップショット](/ja/specifications/node-operators/snapshots)を使用してブートストラップしてください。
* **OP 名前空間の RPC は引き続き使用できますか？** はい、既存の RPC はすべてサポートされています。
